# Fluxo canônico de status do quote (Dema Instalações)

## A ordem é uma SEQUÊNCIA, não um set de flags

Cotações têm um ciclo de vida. Cada status é um ponto nessa sequência, e **a posição importa**: o que vem depois de "approved" (incluindo o próprio approved) **abate a verba**. Não é só `approved`, é **approved + tudo depois**.

## Ordem canônica

Definida em `.fractal/artifacts/dashboard/source/src/utils/budget.js` como `QUOTE_FLOW`:

```
draft      → 0  Rascunho interno
pending    → 1  Em cotação com o fornecedor
quoted     → 2  Cotação recebida do fornecedor
sent       → 3  Enviada para aprovação (cliente/Ademar)
approved   → 4  ★ PRIMEIRA FASE QUE ABATE A VERBA
ordered    → 5  Pedido feito ao fornecedor (continua abatendo)
invoiced   → 6  NF emitida (futuro)
delivered  → 7  Entregue (futuro)
checked    → 8  Conferido (futuro)
done       → 9  Concluído (futuro)
rejected   → saída — não abate
```

## Função utilitária

```js
import { isApprovedOrAfter } from "../utils/budget"

isApprovedOrAfter("approved") === true
isApprovedOrAfter("ordered")  === true
isApprovedOrAfter("done")     === true
isApprovedOrAfter("sent")     === false  // ainda em aprovação
isApprovedOrAfter("quoted")   === false
isApprovedOrAfter("rejected") === false
isApprovedOrAfter(undefined)  === false
```

## Regra de negócio

> **Consumido da verba = soma de `quote.total` onde `isApprovedOrAfter(quote.status) === true`**

Quando uma cotação é marcada como "approved", o valor sai da verba. Se ela avançar para "ordered" (pedido feito), "invoiced" (NF), "delivered" (entregue), etc., o valor **continua abatido** — o compromisso com o fornecedor já foi assumido.

## Implementações que precisam respeitar essa regra

Toda vez que aparecer `q.status === "approved"` no código, é candidato a usar `isApprovedOrAfter(q.status)` em vez disso:

- ✅ `utils/budget.js` — `sumConsumed()` (era `sumApproved`, renomeado)
- ✅ `pages/FornecedorDetailPage.jsx` — `approvedCount` (contava só approved + sent — errado, agora é tudo pós-approved)
- ✅ `pages/PedidosPage.jsx` — `consumedCount` (era `approvedCount + sentCount` — errado, agora é a soma canônica)
- ✅ `pages/ObraDetailPage.jsx` — `BudgetWidget` mostra "em produção" como KPI novo (ordered + invoiced + delivered + checked)

## Outros lugares que ainda precisam ser revisados
