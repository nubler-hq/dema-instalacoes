# Regime de materiais das obras (Dema Instalações)

## Modelo de negócio (Ademar)

Obras Dema podem ter dois regimes de materiais:

- **Contract (Dema compra)**: a Dema tem uma **verba** (saldo) pré-aprovada por contrato. A cada pedido aprovado pelo cliente, o valor é **abatido do saldo**. A Dema é responsável pela compra.
- **Owner (cliente compra)**: o cliente solicita e compra os materiais direto. A Dema só executa o serviço.

## Schema (collection `customers`)

Propriedade opcional `budget`:

```ts
budget: {
  type: z.enum(["contract", "owner"]),
  budget?: number,        // só faz sentido em contract
  notes?: string
}
```

O `budget` é opcional no nível raiz (obras antigas sem essa propriedade continuam funcionando — `getBudgetStatus` retorna `null` e nenhum regime aparece).

## Régua de consumo (regra de negócio)

**Consumido da verba = soma de `quote.total` onde `quote.status === "approved"`**

A aprovação do cliente é o gatilho. Quando o Ademar/quem decide marca o quote como "approved" no fluxo, o valor abate o saldo.

> Próxima evolução: expandir `status` do quote para o fluxo completo:
> `sent → client_approved → invoiced → delivered → checked → done`
> Por enquanto só `approved` abate.

## Régua visual (cores)

- **Verde** (`--green`): < 60% consumido
- **Amarelo** (`--warn`): 60–90% consumido
- **Vermelho** (`--danger`): > 90% consumido ou estourado

## Implementação

- **Schema**: `.fractal/collections/customers/schema.ts` (Zod v4)
- **Helper**: `.fractal/artifacts/dashboard/source/src/utils/budget.js`

  - `getBudgetAggregate(customers, quotes)` → totais do header
- **Visual**:
  - `ObrasPage.jsx` — barra de progresso + chip de regime na lista; KPIs agregados no header
  - `ObraKanban.jsx` — barra compacta + chip nos cards do kanban

## Lições

- Ao editar schema Zod, o JSON Schema gerado já fica disponível no `fractal collections get` automaticamente — não precisa republicar.
- A CLI `fractal collections records update` pode falhar silenciosamente com coerção de tipos (number → string). Para updates simples, **editar o arquivo `.json` direto** é mais seguro, desde que o schema já esteja aceitando.
