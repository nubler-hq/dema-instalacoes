# Drive — One Drive Folder Structure & Standards

## Mission

Define and enforce a **single source of truth** for file organization in the Dema
Instalações One Drive. Every document — whether it is a supplier quote PDF, a
purchase order spreadsheet, or a bid comparison map — must live in a predictable,
hierarchical path that any team member or agent can navigate without guessing.

---

## Folder Hierarchy

The canonical structure follows **4 levels of hierarchy**:

```
Obras/
└── {Obra-Name}/
    └── Pedidos/
        └── {Number}-{Type}/
            ├── Orçamentos/
            └── Mapa de Cotação/
```

### Level 1 — `Obras/`

Fixed root directory. All project/construction-site data lives under this folder.
**Do not** create sibling folders at the root level (e.g. `Clientes/`, `Fornecedores/`).

### Level 2 — `{Obra-Name}`

The name of the obra (construction site or project). Use uppercase, keep names as
short as reasonably identifiable.

| ✅ Correct | ❌ Incorrect |
|---|---|
| `WISE` | `Wise Vila Clementino` |
| `GTZ-84` | `Gattaz 84` |
| `OR-RYT` | `Obra RYT Paulista` |

### Level 3 — `Pedidos/`

Fixed subfolder inside each obra. All purchase orders for that obra live here.
**Do not** rename or move this folder.

### Level 4 — `{Number}-{Type}`

A single purchase order identified by its **sequential number** (zero-padded to 3
digits) and its **material type**.

**No prefix** (do not add `Pedido-` or `PO-` before the number).

| ✅ Correct | ❌ Incorrect |
|---|---|
| `006-Elétrica` | `Pedido-006-Elétrica` |
| `001-Subsolo` | `001-SubSolo` |
| `002-Hidráulica` | `02-Hidraulica` |
| `006-Hidráulica` | `006-Hidraulica` |

**Valid Types:**

| Type | Scope | Examples |
|---|---|---|
| `Elétrica` | Electrical materials | Cables, conduits, boxes, grounding, conduletes, switches |
| `Hidráulica` | Hydraulic/plumbing materials | Pipes, fittings, shaft passants, PVC connections |
| `Subsolo` | Basement/subsystem materials | Waterproofing, drainage, subfloor |
| `Fiação` | Cabling and wiring | Wires, lugs, terminals |
| `Canteiro` | Jobsite/support materials | General supplies, tools, safety equipment |
| `Estrutural` | Structural materials | Steel, rebar, concrete accessories |
| `Fixação` | Fastening/fixing materials | Anchors, bolts, brackets, clamps |

## Folder Internal Structure

Inside each `{Number}-{Type}` folder, exactly **2 subfolders** must exist:

```
{Number}-{Type}/
├── Orçamentos/           ← Original supplier PDFs + normalized XLSX sidecars
└── Mapa de Cotação/     ← Bid comparison spreadsheets, HTML dashboards, JSON data
```

### `Orçamentos/`

Stores the original supplier quote PDF and its normalized Dema spreadsheet. Both
files use the same stem:

```
Orcamento-{Fornecedor}-{Reference}.pdf
Orcamento-{Fornecedor}-{Reference}.xlsx
```

| ✅ Correct | ❌ Incorrect |
|---|---|
| `Orcamento-A3-Eletro-241393.pdf` | `Orçamento Nº 241393.pdf` |
| `Orcamento-Coflex-76782.pdf` | `COTAÇÃO COFLEX N.76782.pdf` |
| `Orcamento-FF-Guarulhos-Complementar-847908.pdf` | `847908.pdf` |

**Rules:**
- Use `Orcamento-` prefix (Portuguese, no cedilla for ASCII safety).
- Supplier name: capitalize first letters, use hyphens between words.
- Reference: the supplier's quote/proposal number, or the email attachment reference.
- If the quote is for supplementary/complementary items, append `-Complementar`.
- **Never** rename the original file when saving — always copy with the standard name.
- The `.xlsx` is generated from the structured `quotes` record and must reconcile
  with the PDF; it never replaces the original evidence.

### `Mapa de Cotação/`

Stores bid comparison documents. These are typically generated by the quote-processing
pipeline and may have multiple formats:

| Format | Naming Pattern | Example |
|---|---|---|
| Excel (.xlsx) | `MAPA_DE_COTACAO_REF_{PEDIDO}_{TIPO}_{OBRA}_{DATA}.xlsx` | `MAPA_DE_COTACAO_REF_006_ELETRICA_WISE_16062026.xlsx` |
| HTML (.html) | `MAPA_DE_COTACAO_REF_{PEDIDO}_{TIPO}_{OBRA}_{DATA}.html` | `MAPA_DE_COTACAO_REF_006_ELETRICA_WISE_16062026.html` |
| JSON (.json) | `MAPA_DE_COTACAO_REF_{PEDIDO}_{TIPO}_{OBRA}_{DATA}.json` | `MAPA_DE_COTACAO_REF_006_ELETRICA_WISE_16062026.json` |
| Dashboard (.xlsx) | `MAPA_DE_COTACAO_REF_{PEDIDO}_{TIPO}_{OBRA}_{DATA}_DASHBOARD.xlsx` | `MAPA_DE_COTACAO_REF_006_ELETRICA_WISE_16062026_DASHBOARD.xlsx` |

## Spreadsheet Naming Convention

Purchase order spreadsheets (`.xlsx`) live **inside the `{Number}-{Type}` folder**
alongside `Orçamentos/` and `Mapa de Cotação/`. Their naming pattern:

```
PEDIDO_{NUMBER}_{TYPE}_{OBRA}_{SUPPLIER}_{REFERENCE}.xlsx
```

| Field | Description | Example |
|---|---|---|
| `NUMBER` | 3-digit zero-padded number | `006` |
| `TYPE` | Material type in Portuguese | `ELETRICA` |
| `OBRA` | Obra name, uppercase, spaces → hyphens | `WISE` |
| `SUPPLIER` | Supplier short name | `ELECON` |
| `REFERENCE` | Supplier reference or PO number | `904963` |

**Examples:**
- `PEDIDO_006_ELETRICA_WISE_ELECON_904963.xlsx`
- `PEDIDO_006_HIDRAULICA_WISE_FF_GUARULHOS_847460_847908.xlsx`
- `PEDIDO_002_ELETRICA_RYT_PAULISTA_FF_GUARULHOS_847627.xlsx`

## Procedures

### A. Organizing New Supplier Quotes

When the user asks to save new supplier quote PDFs into the One Drive:

1. **Identify** the obra from the email subject or user context.
2. **Identify** the pedido number and type.
3. **Verify** the `Obras/{Obra}/Pedidos/{Number}-{Type}/` path exists.
   - If the folder does not exist, **create** it along with `Orçamentos/` and `Mapa de Cotação/`.
4. **Copy** each PDF from the download location to `Orçamentos/` with the standard name:
   ```
   Orcamento-{Supplier}-{Reference}.pdf
   ```
5. **Generate** the normalized spreadsheet beside it with the identical stem:
   ```
   Orcamento-{Supplier}-{Reference}.xlsx
   ```
6. **Confirm** with the user the list of files saved.

### B. Restructuring Existing Folders

When the user asks to reorganize legacy folders into the standard:

1. **Audit** the current structure with `ls -R`.
2. **Map** each existing file to its target `{Number}-{Type}` folder based on:
   - The pedido number embedded in the filename (e.g. `PEDIDO_006_...` → `006-...`).
   - The type embedded in the filename (e.g. `..._ELETRICA_...` → `Elétrica`).
   - The obra folder it currently lives under.
3. **Create** missing target directories.
4. **Move** each file using `mv` (do not copy — move to avoid duplication).
5. **Remove** empty source directories with `rmdir`.
6. **Clean up** any `Mapa de Cotação` folders that were at the obra root level,
   moving their contents into the correct `{Number}-{Type}/Mapa de Cotação/`.
7. **Report** the final structure to the user.

### C. Adding a New Pedido Folder

When creating a folder for a brand new purchase order:

```bash
mkdir -p "Obras/{Obra}/Pedidos/{Number}-{Type}/Orçamentos"
mkdir -p "Obras/{Obra}/Pedidos/{Number}-{Type}/Mapa de Cotação"
```

### D. Archiving a Pedido

When a pedido is fully delivered and closed:

1. **No structural change** — the folder remains in place for historical reference.
2. Optionally, add a `.done` marker file:
   ```
   touch "Obras/{Obra}/Pedidos/{Number}-{Type}/.done"
   ```
3. **Do not** move to an `Archived/` folder — the canonical path is the permanent record.

## Validation Rules

- `{Number}` must always be **3 digits zero-padded** (`001`, `010`, `100`).
- `{Type}` must always be in **Portuguese** with **diacritics preserved** (`Elétrica`, `Hidráulica`).
- `Orçamentos/` must contain only supplier quote evidence pairs (`.pdf` original
  plus `.xlsx` normalized sidecar).
- `Mapa de Cotação/` must contain **only comparison/spreadsheet files**, not supplier PDFs.
- **Never** store files directly in the `{Number}-{Type}` root — always use `Orçamentos/` or `Mapa de Cotação/`.
- **Never** rename a folder after it has been created — the `{Number}-{Type}` is a stable identifier.
- **Never** place a pedido folder directly under the obra root; it must be under `Pedidos/`.
- **Never** use spaces in folder or file names — use hyphens (`-`) or underscores (`_`) instead.
